# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Factory Inventory Management System Demo with GitHub integration - Full-stack application with Vue 3 frontend, Python FastAPI backend, and in-memory mock data (no database).

> ⚠️ **This repository and any fork you create are PUBLIC.** Do not commit credentials, internal hostnames, or private registry URLs. `client/.npmrc` pins the public npm registry and `client/package-lock.json` is gitignored to prevent locally-configured registries from leaking into commits — leave both in place.

## Stack
- **Frontend**: Vue 3 + Composition API + Vite (port 3000)
- **Backend**: Python FastAPI (port 8001)
- **Data**: JSON files in `server/data/` loaded via `server/mock_data.py`

## Quick Start

```bash
# Backend
cd server
uv run python main.py

# Frontend
cd client
npm install && npm run dev
```

Or `./scripts/start.sh` / `./scripts/stop.sh` (macOS/Linux; installs deps if missing).

cd tests && uv run pytest -v

- Vite does not fail when port 3000 is busy; it silently moves to 3001+. Check the startup output. The backend URL is hard-coded in `client/src/api.js` (`http://localhost:8001/api`), and CORS is wide open.
- `server/data/*.json` is regenerated by `server/generate_data.py`; the server only reads the JSON at startup, so restart after editing data.

## Architecture Notes

- **Backend is one file**: `server/main.py` holds the Pydantic models, the shared `apply_filters` / `filter_by_month` helpers, and every route. `server/mock_data.py` loads the JSON files into module-level lists that endpoints filter directly. There is no persistence. Month filtering matches substrings of `order_date`, and quarters come from the hard-coded 2025-only `QUARTER_MAP`.
- **Filter state is a singleton**: `client/src/composables/useFilters.js` keeps module-level refs shared by every view and `FilterBar.vue`. `getCurrentFilters()` maps them to the API params, and `api.js` drops any param equal to `'all'`.
- **i18n and currency**: `client/src/composables/useI18n.js` with `locales/en.js` and `locales/ja.js`. Currency follows locale (en = USD, ja = JPY), formatted via `utils/currency.js`. New UI strings need keys in both locale files.
- **Routing**: `client/src/main.js` registers routes for Dashboard, Inventory, Orders, Demand, Spending and Reports. `views/Backlog.vue` exists but has no route.
- **Nested docs**: `server/CLAUDE.md` has backend conventions (endpoint, filter and error patterns). `tests/README.md` lists the test layout, and its file list may lag the real files.
- **Claude config**: project subagents, slash commands (`/start`, `/stop`, `/test`, `/demo-branch`, `/reset-branch`, `/optimize`) and a tool-usage logging hook live in `.claude/`. `.mcp.json` needs `GITHUB_PERSONAL_ACCESS_TOKEN` in the environment for the GitHub MCP server.

## Key Patterns

**Filter System**: 4 filters (Time Period, Warehouse, Category, Order Status) apply to all data via query params
**Data Flow**: Vue filters → `client/src/api.js` → FastAPI → In-memory filtering → Pydantic validation → Computed properties
**Reactivity**: Raw data in refs (`allOrders`, `inventoryItems`), derived data in computed properties

## API Endpoints
- `GET /api/inventory` - Filters: warehouse, category
- `GET /api/orders` - Filters: warehouse, category, status, month
- `GET /api/dashboard/summary` - All filters
- `GET /api/demand`, `/api/backlog` - No filters
- `GET /api/spending/*` - Summary, monthly, categories, transactions

## Common Issues
1. Use unique keys in v-for (not `index`) - use `sku`, `month`, etc.
2. Validate dates before `.getMonth()` calls
3. Update Pydantic models when changing JSON data structure
4. Inventory filters don't support month (no time dimension)
5. Revenue goals: $800K/month single, $9.6M YTD all months
